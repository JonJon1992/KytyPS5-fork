## Big imports, by area

### d6a807a4 — "2026-09-25 handoff delta" (98 files)
- **EmK530 renderer optimisations**:
  - Region dirty summaries (`MaybeModified`, `KYTY_TRACKER_SKIP_CLEAN`) and a global `g_cpu_dirty_epoch`. Ours has its own epoch machinery: `memoryTracker.h:85-113` `CpuMutationEpoch`/`TakeDirtiedRanges`. The tracker architecture differs, so no direct port.
  - `CommandScheduler::CompleteDraw` flushes every 16 draws (`KYTY_DRAW_FLUSH_INTERVAL`). We lack that exact knob; we have our own submit/flush policy. Optional A/B idea, low priority.
  - RELEASE_MEM batched flushes (32 labels / 8 interrupts). HAVE as `KYTY_EOP_FLUSH_BATCH` (`commandProcessor.h:379`).
  - GPU-wait and semaphore slow-wait stats. HAVE GpuWaits counters (`masterSemaphore.cpp`, `hangTrace.cpp`).
  - Texture-cache GC (`KYTY_GC_DEVICE_BYTES`, `KYTY_GC_KEEP_TILED`), buffer-cache and stream-buffer changes: covered by the cache groups.
- **Bindless textures** (bindlessTable +401/+126, descriptors +297): we have our own bindless (`bindlessTable.cpp`, the bindless-cow work).
- **Non-fatal translation** (`TrackingFailure`, non-fatal CFG build failures, non-fatal tessellation-memory lowering, "gave up" → shader skipped): **we lack this**. On our side those paths EXIT. This is a policy question (skipped draws vs a stop). Flag it to the recompiler group, don't port blindly.
- **AMPR**: the fork's own 1,577-line resolver. N/A: we use upstream's.
- **ATRAC9** `AjmAt9ConfigDataValid` check: minor. We have upstream's `AjmAt9InitDecoder`.
- **Small libs fixes we lack** (PORT-LOW candidates, simple, game-agnostic):
  - Save-data dialog and Msg dialog in progress-bar mode stay RUNNING until Close. Ours returns FINISHED after one RUNNING poll (`src/libs/dialog.cpp:464-476`), and a game then reopens it every frame.
  - libSaveData accepts "legacy" save dirs without `sce_sys`.
- **N/A / diagnostics**: Windows dbghelp host backtrace in asserts, TrackedFault tallies, NV diagnostics feature query, AGENTS.md, launcher bindless checkbox. We already have shader clock, device fault and diagnostic checkpoints (`diagnosticCheckpoints.cpp`).

### c26ad60c — "wolverine-all-changes.patch" rendering merge (44 files)
- Shader function calls (ShaderFunctions.cpp +553), flat LDS/scratch apertures, BVH intersection: **HAVE**. See `frontend/decode/ShaderFunctions.cpp`, `translate/Memory.cpp:747 FLAT_APERTURE`, and `backend/spirv/spirvEmitterBvh.cpp:341/467`. Ours arrived via the earlier int16/int17 ports.
- **DRAW_INDIRECT_MULTI per-draw DrawIndex**: we lack it. The fork reads `buffer[3]` bit 31 (draw-index enable) and writes the loop index into that user SGPR before each draw. Our parser `pm4Handlers.cpp:1716-1740` ignores it. The native multi-draw path would also need `gl_DrawID`, or a CPU fallback when DrawIndex is enabled. It's a correctness gap that matters only if a title enables DrawIndex. **PORT-MED / investigate**: add a one-line log first to see whether Crash/Yotei/Astro ever set that bit.
- Transactional compute dispatches: BDA writes are snapshotted and retried on a missing-page fault, and the host fence is removed. This is a different coherence design from ours (lazy BDA residency, coherence service). SKIP. It belongs to the coherence front.
- Uniform-buffer reads evaluated on the CPU, the SRT planner (PlanScalarReads), integer RT exports, LDS min 1 dword, the V_CMP_EQ_F64 1/(2π) literal fix: recompiler-group items. Not checked line by line here.
- `SynchronizeGpu()` before completion labels/timestamps: the opposite direction from our guest-sync-release-mem deferral. SKIP.
